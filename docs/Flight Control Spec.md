# Fighter Jet Arcade — Flight Control Spec

> เอกสารทิศทางหลักสำหรับ dev และ AI agent
> โปรเจกต์: เกมเครื่องบินรบ arcade บนเว็บ · เมาส์ + คีย์บอร์ด · F-22 / Su-57
> rev.2 — 2026-08-12

## 0. North Star — อ่านก่อนเขียนโค้ดทุกครั้ง

**เกมนี้คือเกม arcade ที่ให้ผู้เล่นรู้สึกเป็นนักบินเก่ง ไม่ใช่เกมที่สอนวิธีเป็นนักบิน**

หลักตัดสินใจ 6 ข้อ ใช้เมื่อไม่แน่ใจว่าควรทำทางไหน:

| # | หลัก | แปลเป็นการตัดสินใจ |
|---|------|--------------------|
| N1 | **Player intent > physical accuracy** | ถ้าฟิสิกส์จริงขัดกับสิ่งที่ผู้เล่นตั้งใจจะทำ ให้ผู้เล่นชนะ |
| N2 | **Energy is the only real resource** | ความเร็วคือทรัพยากร ทุกการกระทำเท่ๆ ต้องจ่ายด้วยความเร็ว |
| N3 | **Skill = timing + intent, not dexterity** | ท่ายากใช้อินพุตง่าย (ปุ่มค้าง + ลากเมาส์) ห้ามมีคอมโบ ห้ามมี QTE ความเก่งวัดจากการเลือกจังหวะและอ่านสถานการณ์ |
| N4 | **Never punish with loss of control** | ห้ามมีสถานะที่ผู้เล่นบังคับไม่ได้เกิน 2 วินาที (ยกเว้นท่าที่ผู้เล่นกดเอง) |
| N5 | **Readable in 1 second** | ทุกข้อมูลที่ต้องใช้ตัดสินใจต้องอ่านจากหน้าจอได้ใน 1 วินาที |
| N6 | **Comfort is a feature, not a setting** | ค่าตั้งต้นต้องไม่ทำให้ใครเมา แล้วค่อยเปิดให้ปรับเพิ่มความรุนแรงได้ |

### Anti-goals — สิ่งที่เกมนี้ตั้งใจไม่ทำ

- ❌ ไม่มี stall/spin ที่กู้คืนไม่ได้
- ❌ ไม่มีการจัดการเชื้อเพลิงหรือกระสุนแบบจริงจัง
- ❌ ไม่มี trim, mixture, flap, landing gear เป็นระบบที่ผู้เล่นต้องคุม
- ❌ ไม่มี checklist หรือขั้นตอนก่อนบิน
- ❌ ไม่ต้องการความแม่นยำเชิงสมรรถนะจริงของอากาศยาน (ใช้ค่าสมดุลเกมเท่านั้น)
- ❌ **ไม่มีท่า scripted ที่ยึดการควบคุมไปจากผู้เล่น** (เปลี่ยนจาก rev.1 — ดูหมวด 4)

## 1. Control Architecture — **Relative Virtual Stick**

โมเดลนี้คือลูกผสมของ Instructor (War Thunder) + Expert control (Ace Combat 7)
และมันแก้ปัญหาอันดับ 1 ของ Battlefield 6 คือ *ต้องยกเมาส์วางใหม่เพื่อเลี้ยวต่อเนื่อง*

### 1.1 สี่ชั้น

```
┌─ Layer 1: INPUT ─────────────────────────────────────────┐
│ Pointer Lock → movementX/Y → สะสมเป็น aimPoint           │
│ aimPoint อยู่ในกรอบกลางจอ ±40% ของ viewport              │
│ ⚠ aimPoint = "ทิศที่อยากไป" ไม่ใช่ "มุมของคันบังคับ"      │
└──────────────────────────────────────────────────────────┘
┌─ Layer 2: INSTRUCTOR ────────────────────────────────────┐
│ angularError = angleBetween(nose, aimPoint)              │
│ สั่ง pitch/yaw ตามสัดส่วน error พร้อม clamp ตาม G-limit  │
│ ทำหน้าที่: กัน stall · auto-trim · จำกัด G · กันชนพื้น   │
└──────────────────────────────────────────────────────────┘
┌─ Layer 3: PLAYER INTENT ─────────────────────────────────┐
│ A/D → roll โดยตรง ไม่ผ่าน Instructor เสมอ                │
│ ผู้เล่นเลือกได้: เลี้ยวแบบเอียงเครื่อง หรือปล่อยให้ระบบทำ  │
└──────────────────────────────────────────────────────────┘
┌─ Layer 4: RECENTRE ──────────────────────────────────────┐
│ ไม่ขยับเมาส์ > 0.30s → aimPoint ไหลกลับกลางจอ            │
│ อัตรา ~2.5 หน่วย/วิ (ease-out) → ไม่ต้องยกเมาส์วางใหม่    │
└──────────────────────────────────────────────────────────┘
```

### 1.2 กติกาผสมอินพุต — **บังคับ**

อินพุตเมาส์กับคีย์บอร์ดต้อง **บวกกัน ไม่ใช่แทนที่กัน**

```js
pitchInput = clamp(mousePitch + keyPitch, -1, 1)
yawInput   = clamp(mouseYaw   + keyRudder, -1, 1)
```

> ⚠️ **ห้ามให้อินพุตหลังเขียนทับอินพุตแรก** นี่คือบั๊กที่ BF6 เจอหลัง Season 1
> (ขยับเมาส์ไปลบล้างปุ่ม pitch ที่กดค้าง) และเป็นสาเหตุที่ผู้เล่นเลิกเล่นเครื่องบิน

### 1.3 Instructor tuning — ระวัง wobble

Instructor คือ PID controller: `setpoint = aimPoint`, `output = control surfaces`
อาการที่ผู้เล่น War Thunder บ่นบ่อยที่สุดคือ **wobble** — เกน P สูงเกินจนเครื่องสั่นตอนเล็ง

- เริ่มจาก P เท่านั้น เพิ่ม D เมื่อเจอ overshoot
- ห้ามใส่ I term (จะสะสมแล้วเครื่องดิ้น)
- ลดเกนลงเมื่อ `angularError` เล็กกว่า 3° เพื่อให้เล็งนิ่ง

## 2. Keybind

หลักคิด: **มือซ้ายอยู่บน WASD ตลอด** ทุกอย่างที่ต้องใช้กลางการต่อสู้อยู่ในระยะนิ้วเดียว

### 2.1 การบิน

| Input | Action | หมายเหตุ |
|-------|--------|----------|
| `Mouse` | Pitch + Yaw | ผ่าน virtual stick |
| `A` / `D` | Roll ซ้าย / ขวา | **ตรงเสมอ ไม่ผ่าน Instructor** |
| `W` / `S` | ต้องการเร็วขึ้น / ช้าลง | `W` สั่ง MIL power, `S` สั่ง idle; ฟิสิกส์เป็นผู้กำหนดความเร็วจริง |
| `W + S` | **Extreme Maneuver** | ขอทั้ง High-G และ PSM พร้อมกัน; คงค่าคันเร่งก่อนเข้า chord |
| `Shift` | Afterburner | คำสั่งแยกจาก MIL power และมี spool delay |
| `Space` | **High-G Turn** | กดค้าง; เลี้ยวคมขึ้นและจ่ายด้วยพลังงาน |
| `X` | **Airbrake** | ทำงานแยกจากคันเร่งและการเลี้ยว |
| `Alt` | **Post-Stall Authority** | กดค้าง; arm PSM — คนละปุ่มกับ High-G โดยตั้งใจ |
| `Q` / `E` | Rudder ซ้าย / ขวา | เล็งละเอียด |

### 2.2 อาวุธ / กล้อง / ระบบ

| Input | Action | หมายเหตุ |
|-------|--------|----------|
| `LMB` | ยิงอาวุธ | ยังไม่ต่อสาย; คลิกแรกคือการส่ง pointer ให้ท้องฟ้า |
| `RMB` | Zoom ที่เป้า | ยังไม่ต่อสาย; ปุ่มถูกจองไว้แล้ว |
| `Tab` | สลับเป้าถัดไป | ยังไม่ต่อสาย |
| `F` | Flare / Chaff | ยังไม่ต่อสาย; ปุ่มถูกสงวนไว้แล้ว (rebind ทับไม่ได้) |
| `1`–`4` | เลือกอาวุธ | ยังไม่ต่อสาย; ปุ่มถูกสงวนไว้แล้ว |
| `C` | สลับกล้อง | Chase ↔ Nose |
| `MMB` (ลาก) | Freelook | ไม่เปลี่ยนวิถีบิน |
| `R` (ค้าง) | มองข้างหลัง | เครื่องบินยังอยู่ในเฟรม |

### 2.3 เหตุผลที่ต้องรู้

**ทำไม A/D = roll ไม่ใช่ yaw**
BF6 วาง A/D เป็น yaw เพราะเมาส์คุม roll อยู่แล้ว แต่ในโมเดลเราเมาส์คุม *ทิศ* ไม่ใช่ roll ผู้เล่นจึงต้องมี roll แบบตรงไปตรงมา — AC7 พิสูจน์ว่าการถอด roll ออก (โหมด Novice) ทำให้หลบมิสไซล์ใน multiplayer แทบไม่ได้

**ทำไมไม่ใช้ scroll wheel เป็นคันเร่ง**
บนเบราว์เซอร์ scroll เสี่ยงถูกหน้าเว็บดักไป และการเร่งต้องทำพร้อมเลี้ยว

**ต้องมี pitch สำรองบนคีย์บอร์ด (ตัวเลือกใน settings)**
ผู้เล่น BF6 จำนวนมากผูก pitch ไว้บนปุ่มเองแล้วบอกว่าบินง่ายขึ้นทันที — เปิดทางนี้ไว้ตั้งแต่แรก

**ทำไม W/S คุม intent ไม่คุมความเร็วโดยตรง**
`W` หมายถึงต้องการกำลังแห้งสูงสุดและ `S` หมายถึงต้องการกำลังต่ำ เครื่องยนต์ต้อง spool
และความเร็วต้องเกิดจาก thrust ลบ drag เท่านั้น ช่วงไม่กด W/S มี soft power assist ที่ชดเชย
เฉพาะ parasite drag โดยไม่มี target speed จึงยังเสียความเร็วจากการไต่หรือ High-G ได้

**ทำไมนิ้วโป้ง (Space) ได้ High-G ไม่ใช่ airbrake**
ทั้งคู่เป็นการกดค้างยาว แต่ใน dogfight High-G คือปุ่มที่ค้างบ่อยที่สุด นิ้วโป้งจึงควรได้ปุ่มนั้น
airbrake ย้ายไป `X` ซึ่งนิ้วนางกดค้างได้โดยไม่ทิ้ง WASD และไม่ชนกับ shortcut ของเบราว์เซอร์เหมือน Ctrl
> ⚠ ต้อง `preventDefault` บน Space เพื่อกัน scroll ของหน้าเว็บ

**ทำไม High-G กับ PSM ต้องแยกปุ่ม**
ในย่านที่ PSM arm ได้ (220–660 km/h) "เลี้ยวแรง" กับ "เข้า Cobra" คือ stick เดียวกัน กดค้างเท่ากัน
ไม่มีสัญญาณฝั่ง input ใดแยกสองอย่างนี้ออกจากกันได้ ปุ่มเดียวจึงแปลว่าการเลี้ยวแรงทุกครั้งในย่านรบ
กลายเป็น post-stall tumble — `W + S` ยังขอทั้งคู่พร้อมกันได้ แต่นั่นคือ chord ที่ผู้เล่นตั้งใจกด

### 2.4 X — Airbrake อิสระ

X สั่งแผ่น airbrake อย่างเดียวและไม่เปลี่ยน throttle ผู้เล่นจึงใช้ `W + X`
หรือ `S + X` ได้ทั้งหมด การกาง/เก็บต้อง smooth และเพิ่ม aerodynamic drag ห้ามลบความเร็วตรงๆ

**ราคา = ความเร็วที่ตกลงเท่านั้น ไม่มีมาตรวัด ไม่มีคูลดาวน์**
อ่านออกจากเข็มความเร็วได้ใน 1 วินาที (N5) และมันจำกัดตัวเองอยู่แล้ว — กดนานไปก็ช้าจนเปราะ ไม่ต้องมีระบบลงโทษเพิ่ม

## 3. Physics

> **ไม่ต้องการอากาศพลศาสตร์จริง ต้องการเศรษฐศาสตร์ของพลังงาน**
> ผู้เล่นต้องรู้สึกว่าความเร็วคือทรัพยากรที่ใช้แล้วหมด — นั่นคือสิ่งที่ทำให้ dogfight มีการตัดสินใจ

### 3.1 Core loop — เจ็ดบรรทัดนี้ให้พฤติกรรมราว 90% ของสิ่งที่ผู้เล่นรู้สึก

```js
engineThrottle = moveTowards(engineThrottle, commandedThrottle, spoolRate * dt)
thrust = thrustCurve(v, altitude) * engineThrottle * afterburnerMultiplier
parasiteDrag = Cd0 * v*v
inducedDrag = k * max(G - 1, 0) ** 2 * v*v
airbrakeDrag = airbrakeAmount * airbrakeCoefficient * v*v
v += (thrust - parasiteDrag - inducedDrag - airbrakeDrag) / mass * dt

turnRate = maxTurn * liftCurve(v) * gLimit(v)
heading  = slerp(heading, targetDir, turnRate * dt)

velocity = lerp(velocity, heading * v, momentumLag * dt)   // ความหน่วง
```

### 3.2 ต้องมี

| ระบบ | ทำอะไร | ทำไมจำเป็น |
|------|--------|-----------|
| **Energy trade** | drag เพิ่มตามกำลังสองของ G ที่ดึง | กลไก*เดียว*ที่สร้างการตัดสินใจในการไล่ล่า ดึงหนัก → เข็มความเร็วตกให้เห็น |
| **Corner speed** | อัตราเลี้ยวสูงสุดอยู่ที่ความเร็วช่วงกลาง | ให้ผู้เล่นเรียนรู้เอง — แสดงเป็นแถบสีบนมาตรวัดความเร็ว |
| **Momentum lag** | velocity vector ตามหลัง nose เล็กน้อยตอนเลี้ยวแรง | เครื่องมีน้ำหนัก โดยไม่ต้องจำลอง sideslip จริง |
| **Thrust vectoring** | ค่าประจำเครื่อง เปิดสิทธิ์ท่า post-stall | ทำให้ F-22 กับ Su-57 ต่างกันอย่างมีเหตุผล |
| **Engine spool + auto assist** | W/S สั่ง intent; neutral ชดเชยเฉพาะ parasite drag | คุมง่ายแต่ไม่คืนพลังงานที่เสียจาก High-G |

### 3.3 ไม่ต้องมี

| ระบบ | ทำแทนด้วย |
|------|-----------|
| Stall / spin ที่ลงโทษ | Instructor กันไว้ ถ้าช้ามากให้หัวตกแบบนุ่มและกู้เองได้ (N4) |
| เชื้อเพลิง | มาตรวัด afterburner ที่เติมเองได้ |
| กระสุน / มิสไซล์จำกัด | ปืนไม่จำกัด · มิสไซล์เติมตามเวลา |
| ลม / สภาพอากาศ | ไม่มี — เป็น noise ที่ผู้เล่นควบคุมไม่ได้ |

## 4. Maneuvers — **Post-Stall Authority ไม่ใช่ท่า scripted**

> ผู้เล่น**บินท่านั้นเอง** ระบบแค่ปลดล็อกขอบเขตให้ทำได้ (N1, N4)

`Ctrl` (ค้าง) = **Post-Stall Authority (PSA)**
ระหว่างกด: Instructor หยุดจำกัด AoA และ G · thrust vectoring ทำงานเต็มกำลัง · เครื่องหมุนรอบจุดศูนย์ถ่วงได้แม้ปีกไม่มีแรงยกแล้ว

ท่าจึงไม่ใช่รายการที่เลือก แต่เป็น **ผลของสิ่งที่เมาส์ทำ** ระหว่างกด `Ctrl`:

| ท่า | ผู้เล่นทำอะไร | เครื่องทำอะไร |
|-----|--------------|---------------|
| **Pugachev's Cobra** | ลากเมาส์ขึ้นจนหัวชี้ 90–120° แล้ว**ปล่อย** → ลากลงเมื่อพอใจ | หัวค้างมุมนั้นไว้ ~1.0s-3.0s แล้วไหลกลับตามแรงโน้มถ่วง วิถีบินยังพุ่งไปข้างหน้า |
| **Kulbit** | ลากเมาส์ขึ้น**ค้างไว้ไม่ปล่อย** | หมุนต่อเนื่องเป็นวงรัศมีแคบมาก ครบรอบแล้วอยู่ที่เดิม |
| **Immelmann** | ลากขึ้นค้างจนหัวกลับทาง 180° แล้วปล่อย `Ctrl` + เร่ง | roll กลับหงายเองแล้วพุ่งออก — เปลี่ยนทิศพร้อมได้ระดับความสูง |
| **J-turn / Herbst** | ลากเมาส์ไปข้างขณะความเร็วต่ำ | หัวกวาดข้าง 180° โดยเวกเตอร์ความเร็วยังพุ่งทิศเดิมอยู่ครู่หนึ่ง |
| **Tail Slide** | ลากขึ้นจนหัวชี้ 80–90° แล้ว**ปล่อยเมาส์ และไม่แตะคันเร่ง** | v ไหลลงถึง 0 เครื่องหยุดกลางอากาศ แล้วเริ่มไถลถอยหลังแบบ tail-first · กดหัวลงเพื่อออกจากท่า ดู 4.2 |

### 4.1 Nose-hold — กฎที่ทำให้ Cobra รู้สึกเป็น Cobra

เมื่อ**ปล่อยเมาส์**ระหว่าง PSA หัวเครื่องต้อง **ค้างมุมนั้นไว้** ห้ามสปริงกลับเข้าแนวลม

- hold ~1.0s-3.0s แล้วค่อยๆ ไหลกลับแบบนุ่ม (ไม่ใช่สแนป)
- ระหว่าง hold ผู้เล่นยังบังคับทุกแกนได้ตลอด — ไม่มีวินาทีไหนที่คุมไม่ได้ (N4)
- ปล่อย `Ctrl` เมื่อไหร่ก็ได้ → Instructor กลับมาคุมทันที พาหัวกลับแนวลมแบบนุ่ม **ไม่มีบทลงโทษ ไม่มี spin**

### 4.2 Tail Slide — ท่าเดียวที่ความเร็วติดลบ

ต่อยอดจาก Cobra แต่ไม่กดหัวกลับ ปล่อยให้ความเร็วหมดจริง

```
1. ลากขึ้น 80–90°           → เข้าท่า (เหมือน Cobra)
2. ปล่อยเมาส์ · ไม่แตะ W/S  → nose-hold ค้างมุมไว้ · v ตกอิสระถึง 0
3. v ผ่าน 0 เป็นลบ          → ไถลถอยหลัง tail-first เร่งตามแรงโน้มถ่วง
4. ลากเมาส์ลง               → หัวปักลง · v กลับเป็นบวก · สร้างความเร็วใหม่
```

**เงื่อนไขที่ท่านี้ต่างจากทุกท่า**

| ประเด็น | กติกา |
|---------|-------|
| Instructor | ห้ามเข้าไปแก้ตอน v ใกล้ 0 — nose-hold ยาวกว่าปกติ ค้างจนผู้เล่นสั่งออกเอง |
| การบังคับ | พื้นบังคับตาย เหลือ **thrust vectoring เท่านั้น** → หมุนได้ช้าลงมาก แต่ผู้เล่นยังคุมได้ตลอด (N4) |
| เวลาไถลถอยหลัง | เพดาน ~1.5s แล้วบังคับเข้าโหมดปักหัวเอง กันสถานะที่ผู้เล่นค้างนานเกิน |
| แตะคันเร่ง | ถ้ากด `W` หรือ `Shift` ระหว่างข้อ 2 → ออกจากท่าทันที กลายเป็นไต่ชันปกติ |
| ความสูง | ต้องมี AGL เหลือพอ ไม่ผ่านเกณฑ์ → HUD เตือน แล้ว Instructor พาหัวกลับแนวลม |

**ราคาและผลตอบแทน — สุดขั้วที่สุดในเกม**
v = 0 คือสถานะที่เปราะที่สุดที่ผู้เล่นทำได้ ไม่มีพลังงานเหลือเลย เป็นเป้านิ่งกลางอากาศ
แลกกับ: ศัตรูที่ไล่**พุ่งเลยไปในแนวดิ่ง** แก้ไม่ทันเพราะต้องเบรกในแนวตั้ง · เรดาร์ที่กรอง doppler เสียการล็อกเพราะอัตราเข้าใกล้เป็นศูนย์ · ปืนเล็งนำไม่ได้เพราะเป้าไม่เคลื่อน
→ ท่าที่ให้ผลตอบแทนสูงสุด และถ้าอ่านจังหวะพลาดคือตายทันที ตรงกับ N3 พอดี

**FX:** ไอน้ำหายไปหมดตอน v = 0 (เงียบผิดปกติ) · เสียงลมเงียบลงจนได้ยินแต่เครื่องยนต์ · กล้องลอยขึ้นเหนือลำแล้วค้าง · เมื่อเริ่มไถลถอยหลัง เส้นลมกลับทิศ

### 4.3 ไม่มีคูลดาวน์ ไม่มีมาตรวัด — ความเร็วจำกัดตัวเอง

| ความเร็วขณะกด `W + S` หรือ `Alt` | ผลที่ได้ |
|---------------------|----------|
| สูงกว่า corner speed | ได้แค่ G เพิ่มขึ้น หัวไม่พลิก — แรงอากาศชนะ |
| ต่ำกว่า ~40% top speed | pivot ได้เต็มที่ ← **โซนที่ท่าพิเศษเกิดขึ้นจริง** |
| จบท่า | v เหลือน้อย เครื่องเปราะที่สุด — นั่นคือราคาทั้งหมด |

→ ผู้เล่นต้องเบรกด้วย `X` เพื่อลงมาอยู่ในโซน PSA ก่อน **สองปุ่มนี้จึงทำงานเป็นคู่** และไม่ต้องมีระบบลงโทษอื่นเลย

### 4.4 HUD ต้องบอกชื่อท่าที่กำลังทำ

ตรวจจับ pattern จากมุมและอัตราการหมุนย้อนหลัง แล้วขึ้นชื่อกลางจอ: `COBRA` · `KULBIT` · `IMMELMANN` · `HERBST` · `TAIL SLIDE`
ผู้เล่นเรียนรู้คำศัพท์เองจากการบิน และรู้ว่าสิ่งที่ทำไปนับเป็นท่าจริง — สอนเกมโดยไม่ต้องมี tutorial

## 6. Camera — เร้าใจโดยไม่เวียนหัว

อาการเมาเกิดจากตาเห็นการเคลื่อนไหวแต่หูชั้นในไม่รู้สึก
ตัวกระตุ้นแรงที่สุดคือ **การหมุนรอบแกนสายตา** และ **FOV ที่แคบ**
ทั้งสองแก้ได้ด้วยการออกแบบกล้อง ไม่ใช่ลดความเร็วเกม

### 6.1 Defaults

| ค่า | Default |
|-----|---------|
| FOV ขณะบินปกติ | `88°` |
| FOV ขณะ afterburner | `104°` |
| ระยะเวลาเปลี่ยน FOV | `0.45s` |
| Chase follow lag | `0.12s` |
| กล้องหมุนตาม roll | `60%` ของจริง |
| Camera shake | เฉพาะตอนโดนยิง |

### 6.2 กฎสี่ข้อ

1. **อย่าให้กล้องหมุนตาม roll เต็ม 100%** ให้ตามแค่ ~60% แล้วค่อยๆ ปรับกลับสู่แนวราบ — ขอบฟ้าที่หมุนรอบตัวคือสาเหตุอันดับ 1 ของอาการเมา
2. **ความเร็วสื่อด้วยของรอบตัว ไม่ใช่การสั่น** ใช้เส้นลม อนุภาค เอฟเฟกต์ขอบจอ และ FOV ที่ขยาย แทนการเขย่ากล้อง
3. **กล้องจับเป้าอัตโนมัติเมื่อล็อก** เยื้องไปทางศัตรูเล็กน้อย ผู้เล่นไม่ต้องเดาว่าคู่ต่อสู้อยู่ไหน และภาพดูเป็นหนัง
4. **ตั้งค่าให้ปิดได้ทุกอย่าง** FOV · shake · motion blur · roll-follow ต้องมีสไลเดอร์ในเมนู ผู้เล่นแต่ละคนไวไม่เท่ากัน (N6)

### 6.3 Cinematic moments

| จังหวะ | กล้องทำอะไร |
|--------|-------------|
| มิสไซล์ออกจากราง (ระยะไกล) | ตัดไปตามมิสไซล์ ~0.5s · ข้ามได้ด้วยการขยับเมาส์ |
| ระหว่างท่าพิเศษ | ถอยออกกว้างให้เห็นทั้งลำ แล้วกลับเข้าที่เดิม |
| เฉียดพื้น / ผ่านช่องแคบ | ขยาย FOV ชั่วครู่ + เสียงลม |

## 10. Definition of done — checklist ต่อ feature

ก่อน merge งานที่แตะระบบควบคุม กล้อง หรือฟิสิกส์ ให้เช็ก:

- [ ] อินพุตเมาส์ + คีย์บอร์ด **บวกกัน** ไม่มีตัวไหนเขียนทับตัวไหน
- [ ] ไม่มีสถานะที่ผู้เล่นบังคับไม่ได้เกิน 2 วินาที (นอกจากท่าที่กดเอง)
- [ ] ไม่ต้องยกเมาส์วางใหม่เพื่อเลี้ยวต่อเนื่องในทุกสถานการณ์
- [ ] เล่นต่อเนื่อง 10 นาทีด้วยค่าตั้งต้นแล้วไม่เมา
- [ ] ทุกการกระทำที่ให้ผลดีมี cost เป็นความเร็วที่มองเห็นได้บนมาตรวัด
- [ ] ข้อมูลที่ต้องใช้ตัดสินใจอ่านได้ใน 1 วินาที
- [ ] ค่าที่กระทบ comfort (FOV, shake, blur, roll-follow) ปรับได้ในเมนู
- [ ] ปล่อย W/S แล้ว throttle และความเร็วไม่กระโดด; climb/turn ยังเสียพลังงานได้
- [ ] `W + S` เข้า Extreme โดยคง throttle intent เดิม และปล่อยหนึ่งปุ่มแล้วกลับทันที
- [ ] `X` เพิ่ม drag แยกจาก throttle; `W + X` และ `S + X` ใช้ได้
- [ ] `Space` เปิด High-G เท่านั้น และไม่เคย arm PSM ด้วยตัวเอง
- [ ] ปล่อยเมาส์ระหว่าง PSA แล้วหัว**ค้างมุม** ไม่สปริงกลับ
- [ ] ปล่อย `Ctrl` ที่มุมใดก็ได้ แล้วกู้คืนได้ทันทีโดยไม่มี spin
- [ ] `Space` ไม่ทำให้หน้าเว็บ scroll
- [ ] Tail Slide: v ติดลบได้จริง และผู้เล่นยังบังคับหัวได้ตลอดช่วงไถลถอยหลัง
